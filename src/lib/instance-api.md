# Instance API helpers (`src/lib/instance-api.ts`) — endpoint contract

Referenced from `src/app/[orgId]/AGENTS.md` (**Instance API**). Helper →
endpoint inventory for `/api/client/v1` + `/api/install/v1`. **Update this
file whenever those endpoints or `instance-api.ts` helpers change.**

Types and helpers: `src/lib/instance-api.ts` (auth, install, org servers, health). Update when `/api/client/v1` or `/api/install/v1` endpoints change.

Authentication helpers (every 2FA / passkey route is mounted under `/api/client/v1/auth`):

- `signIn(email, password)` → `POST /auth/sign-in` — returns **either** a `SessionInfo` **or** a `TwoFactorChallenge` (`{ requires2fa: true, challenge }`). Narrow with `isTwoFactorChallenge(result)`; the challenge is opaque and short-lived, and is the only thing `signInTwoFactor` needs. Callers must not treat the challenge as a session — `useSignIn` deliberately leaves the session cache untouched for it.
- `SessionInfo.is2faEnabled?: boolean` — present when the control plane projects it; spread conditionally like `needsInstall`, so an older instance reads as `undefined` rather than `false`.
- `signInTwoFactor(challenge, code, kind = 'totp')` → `POST /auth/sign-in/2fa` — one body key decided by `kind`: `code` for an authenticator code, `backupCode` for a one-time code (`TwoFactorCodeKind`). Returns the `SessionInfo` the first step withheld.
- `fetchInstallStatus()` → `GET /status` — `InstallStatus` includes `authProviders?: ('github' | 'google')[]` (providers with client credentials configured). `fetchInstallStatus` always fills it (unknown ids dropped; older instances → `[]`), same style as `billingEnabled`.
- `fetchTwoFactorStatus()` → `GET /auth/2fa` — `TwoFactorStatus`: `{ enabled, method: 'totp' | null, backupCodesRemaining, passkeys: PasskeyRecord[], linkedProviders: ('github' | 'google')[] }`. **The Security screen uses this projection for passkey summaries and the linked-provider list** — there is **no `GET /auth/oauth`**. Passkey rows include `deviceType` / `isBackedUp` (same shape as `GET /auth/passkeys`); `toPasskeyRecords` still defaults omitted fields to `null` / `false` for older payloads. `linkedProviders` defaults to `[]` and is filtered to the known provider ids.
- `enrollTotp(password?)` → `POST /auth/2fa/totp/enroll` — `{ secret, otpauthUri }`. The secret is base32 for manual entry; the URI is the `otpauth://` link. Nothing is enabled until verify succeeds.
- `verifyTotp(code)` → `POST /auth/2fa/totp/verify` — `{ backupCodes }`, **shown once**. This is the only call that returns them on enrollment.
- `regenerateBackupCodes(password?)` → `POST /auth/2fa/backup-codes/regenerate` — `{ backupCodes }`, also show-once; the previous set stops working immediately.
- `disableTwoFactor(password?, code?)` → `POST /auth/2fa/disable`.
- `passkeyRegisterOptions(password?)` → `POST /auth/passkeys/register/options` — `PasskeyCeremonyOptions` (`{ challenge, options }`): `options` goes to `navigator.credentials.create`, `challenge` is the signed envelope to echo back.
- `passkeyRegisterVerify(challenge, name, credential)` → `POST /auth/passkeys/register/verify` — `{ ok, id }`.
- `deletePasskey(id, password?)` → `DELETE /auth/passkeys/:id`.
- `oauthStartUrl(provider, opts?)` → **URL builder, not a fetch** — `${CLIENT_API}/auth/oauth/${provider}/start` plus `redirectTo` / `link=1` query params. The start route answers **302** to the provider; `fetch` would consume the redirect. Same pattern as `githubAppInstallUrl`. Sign-in passes `redirectTo` from `signInOAuthRedirect(pathname, params)` (current `/sign-in` plus leftover query; inbound `error` / `challenge` omitted).
- `unlinkProvider(provider, password?)` → `DELETE /auth/oauth/${provider}` — same optional step-up body as `deletePasskey`. **409** `last_sign_in_method` when this is the last way to sign in.
- `fetchAuthProviderSettings()` / `saveAuthProviderSettings(settings)` → `GET` / `PUT /api/admin/v1/settings/auth-providers` — `{ ok: true, settings }` wrapper, identical to `fetchEmailSettings` / `saveEmailSettings` (`EmailSettingEntry` / `EmailSettingSource` reused).
- `passkeyLoginOptions()` → `POST /auth/passkeys/login/options` — public (no session); rate-limited server-side.
- `passkeyLoginVerify(challenge, credential)` → `POST /auth/passkeys/login/verify` — `SessionInfo`.
- **Step-up rule:** every `password?` above is optional in the helper, but the control plane demands it on every security mutation for an account that has a password — a fresh session never substitutes (`reauth.ts`); only a passkey- or provider-only account is let through on a session younger than 15 minutes. The route answers **403** `Reauthentication required` otherwise. The global forbidden seam blanks a 403's message (`error: null`), so security-screen callers run the result through `resolveSecurityAction` (`src/lib/security-actions.ts`) to tell "confirm your password" apart from a real failure.
- **Ask again before permanent actions** (organization setting): `fetchOrgReauthSettings(orgId)` / `saveOrgReauthSettings(orgId, { requireReauthForDestructive })` → `GET` / `PUT /organizations/:id/reauth-settings` (PUT is owner-only). When it is on, a permanent action answers **403** `{ error: 'reauth_required', action, methods }`. Every request in `instance-api.ts` goes through `fetchWithStepUp` (`src/lib/step-up.ts`), which asks the mounted `ReauthSheet` for a proof and retries the same request once; cancelling returns the original refusal. `submitReauth({ password } | { code })` → `POST /auth/reauth` (a plain `fetch` on purpose, so a wrong proof never re-opens the sheet; 403 wrong, 429 throttled). `methods` is `['totp']` for people with an authenticator, `['password']` otherwise, `['signin']` for passkey / provider-only accounts (sign in again).
- **Ceremony encoding:** the control plane base64url-encodes every binary field and expects the credential back the same way. `src/lib/passkey-client.*` is the only place that converts — never hand `navigator.credentials` a raw server payload, and never post a `PublicKeyCredential` without serializing it. Native returns `{ supported: false }` (render `PASSKEY_WEB_ONLY_NOTE`); that is an answer, not an error.

Authorization helpers:

- `GET /api/client/v1/permissions` → `fetchPermissions()`
- `GET /api/client/v1/access?resourceId=<uuid>` → `fetchAccessGrants(resourceId)` — returns `{ access: AccessGrantRecord[] }`; each row carries `subjectKind`, `subjectId`, `resourceId`, `effect`, and `permissionKey`
- `GET /api/client/v1/access/resource-id?kind=<organization|team>&itemId=<uuid>` → `resolveResourceId(kind, itemId)`
- `GET /api/client/v1/access/check?resourceId=<uuid>&permissionKey=<key>` → `checkPermission(resourceId, permissionKey)`. Any entity's own UUID is its resource id, so `useCan` looks up only organization and team ids and checks a server or managed cluster by its id directly (resource-id answers 404 for those kinds).
- `POST /api/client/v1/access` → `createAccessGrant(body: CreateAccessBody)` — body: `{ resourceId, subjectKind, subjectId, effect, permissionKey }`; grant targets are organization or team entities only
- `DELETE /api/client/v1/access/:id` → `revokeAccessGrant(id)`
- `POST /api/client/v1/invitations` → `createInvitation({ teamId, email, grants? })`
- `GET /api/client/v1/invitations` → `listInvitations()` — `{ invitations: InvitationRecord[] }` (`id`, `email`, `teamId`, `teamName`, `expiresAt`, `createdAt`, `invitedBy`)
- `DELETE /api/client/v1/invitations/:id` → `revokeInvitation(id)`
- `POST /api/client/v1/invitations/:id/accept` → `acceptInvitation(id)`
- `signUp(email, password, invitationId?)` → `POST /auth/sign-up` — optional `invitationId` gates sign-up while public sign-up is disabled when the pending invite matches the email
- `fetchVisibleWorkspaces()` → `GET /api/client/v1/workspaces` — each row includes `kind` (`'turbopanel' | 'user'`); never infer platform from `name`
- `restartSystemComponent(serverId, component)` → `POST /api/client/v1/servers/:id/system/:component/restart` — `CommandEnqueueResponse` + `serverId`; errors `unknown_system_component` / `system_component_not_provisioned` / `system_reconcile_unavailable`; descendant mutations may return **403** `system_resource_immutable`
- `systemComponentLabel()` in `src/lib/system-inventory.ts` — `hosting-ingress` → HTTP/HTTPS Ingress, `managed-ingress` → Database Ingress, `managed-ha` → Database High-Availability, `turbopanel` → Self Hosted TurboPanel Instance; they mirror the control-plane project display names; unknown keys fall through to the raw key
- `ProjectRecord.metadata.component` — optional internal system-component idempotency key (e.g. `hosting-ingress`); never an authorization source
- `ProjectRecord.kind` (`compose` | `managed` | `system`, `null` for a draft; a template is `compose` with `metadata.code`) and `ProjectRecord.icon` (a key from `PROJECT_ICON_KEYS`, or `null`) replaced `metadata.type`; the read-side `system` kind is `SYSTEM_PROJECT_KIND`; `isSystemProject` / `projectTypeLabel` (returns `TURBOPANEL_WORKSPACE_BADGE_LABEL`) / `systemProjectAllowsMutations()` in `src/lib/project-navigation.ts` are the display helpers; read-only behavior is still gated by `isTurbopanelProject` (workspace kind), never by type
- `fetchVisibleProjects(workspaceId?)` → `GET /api/client/v1/projects` (optional `?workspaceId=` filter)
- `createProject({ type: 'empty' | 'docker-compose' | 'template' | 'managed', code?, options?, serverId?, … })` — `type` is **required**. The create wizard sends the **final** type (plus `code` for template/managed, plus `options.compose` for a drafted compose file) in one call, so `type: 'empty'` + `POST …/configure` is now only the resumable path for projects that already exist untyped. A blank compose draft omits `options` entirely and the control plane seeds `emptyComposeDocument()`; an invalid one comes back **400** `compose_invalid`. Project/workspace names are unique per org (trim + case-insensitive; **409** `project_name_in_use` / `workspace_name_in_use`). Managed create may pass `serverId` to pin the scaffolded default environment. `system` is read-only and never sent from the client
- `updateProject` / `updateEnvironment` accept `options.compose` as a ComposeDocument (`src/lib/compose/`); `updateProject` also accepts `options.containerNaming` (`uuid` \| `custom`)
- `deployEnvironment(environmentId, body?)` → `POST /api/client/v1/environments/:id/deploy`; body may include `acknowledgeHealthCheckWarnings` and/or `noCache` (cacheless redeploy → daemon `docker compose build --no-cache --pull` before `up`); the UI always requires placement (`environment.serverId` or project default) first; poll with `fetchCommand(serverId, commandId)` (Postgres only). **`422 fabric_reconcile_failed`** / **`409 fabric_reconcile_pending`** surface as TurboFabric copy in `deployErrorMessage` (never “WireGuard” / `tp0`)
- `fetchDeployPreview(environmentId)` → `GET /api/client/v1/environments/:id/deploy-preview` — `DeployPreviewResponse` (compiled `compose.yaml` snapshot with `role: 'runtime'`, optional `servers[]` per-host compile, `envFile`, `secretPlan[]`, `nativeAppVariables[]` (per Node app: every environment variable its process gets — `name`, `source` scope, `isSecret`, `value` (null for a secret), `delivered`, `reason` when not passed; the deploy preview panel lists them with `nativeAppVariableLine`), `projectName`, `containers[]`, `volumes[]`, `warnings[]`); secret values redacted; same prepare path as deploy. Preview fetch does not require an environment pin; **409** `server_placement_required` is the “select a server” gate.
- `fetchEnvironmentConfigView(environmentId)` → `GET /api/client/v1/environments/:id/config-view` — `EnvironmentConfigViewResponse` `{ ok, environmentId, projectId, isPrimary, standsAlone, base, effective, changes[] }`; `base` / `effective` are `ConfigViewSide` `{ services[], variables[], linuxUsers[] }`, `changes[]` are `ConfigViewChange` (`key`, `area`, `label`, `kind` `added` / `changed` / `removed`, `baseValue` / `envValue` with `baseSource` / `envSource`, `masked`). Read-only, derived on the server (the ui never re-implements the compose merge); `standsAlone` is derived from the saved compose (`services: !override` / `!reset`); every service, field row, Linux user and variable carries `inheritedFromBase` (true when its value comes from the Base and this environment does not set it); secret variables and credential-looking values carry no value (`masked`). **422** `compose_invalid` when a saved compose cannot be read.
- `stopEnvironment(environmentId)` → `POST /api/client/v1/environments/:id/stop` — compose down (with volumes) on `environment.server_id`; returns `{ commandId, serverId }` for polling; used by the project-delete wizard before cascade delete
- `cancelDeployment(environmentId, deploymentId)` → `POST /api/client/v1/environments/:id/deployments/:deploymentId/cancel` — cancels a running or queued deploy (the whole deploy, every host; `deploymentId` is the deploy command id). `{ ok, state: 'cancelled' | 'cancelling' | 'already_cancelled', environmentId, deploymentId }`. **409** `deploy_not_cancellable` (already finished) / `deploy_too_late` (already switching over, it will finish) / `cancel_unsupported` (the server's daemon is too old); **503** `daemon_unavailable`; both have plain copy in `user-error.ts`. No step-up: a re-deploy reverses it. History entries carry `cancelRequestedAt`; terminal status `cancelled`.
- `runEnvironmentLifecycle(environmentId, action)` → `POST /api/client/v1/environments/:id/lifecycle` (`start` / `stop` / `restart`); non-destructive `environment.lifecycle` command; returns `CommandEnqueueResponse`
- `fetchRepositories()` → `GET /api/client/v1/repositories` — `{ repositories: RepositoryRecord[] }`, the org-owned Git repository bindings a compose service attaches to by `sourceId` (the compose document key is still `x-turbopanel.source`). The list carries **no** webhook fields. Exactly one row per repository per organization: `repositoryUrl` is stored canonicalized (lower-cased host, `.git` suffix) and both create lanes are idempotent against it. Rows are created by `attachRepository()` / `createRepository()` from the project flows and managed on the org-level **Repositories** screen (`projects/repositories`, `repositories-section.tsx`).
- `fetchRepository(id)` → `GET /api/client/v1/repositories/:id` — `{ repository: RepositoryDetailRecord }`: the row plus instance-wide `webhookUrl` / `webhookReachable` / `reachabilityNote`, attached **only** for `github` / `gitlab` (a generic `git` repository has no provider webhook), which is why the three are optional rather than nullable. Each call re-resolves the instance public-URL list, so `useRepositoryDetail` is `enabled: false` by default and a row opts in while expanded — never fetch it per listed row
- `createRepository(body)` / `updateRepository(id, patch)` → `POST` / `PATCH /api/client/v1/repositories[/:id]` — `autoDeploy` (`immediate` / `checks_passed` / `disabled`) is a property of the **row**, so editing it affects every service bound to that repository. `createRepository` is **find-or-create** on the canonical clone URL and returns `{ ok, id, reused }` — `reused: true` means the org already held this URL and no row was made (the existing row is never mutated by a reuse); surface it, don't discard it. PATCH may answer **409** `source_url_conflict` (`REPOSITORY_URL_CONFLICT_ERROR`) when a changed URL canonicalizes onto another row
- `refreshRepository(id)` → `POST /api/client/v1/repositories/:id/refresh` — re-reads the provider's current default branch into `metadata.detectedDefaultBranch` / `defaultBranchCheckedAt`; the `defaultBranch` column follows only while the operator has not set an explicit branch. **400** `source_refresh_not_supported` (`REPOSITORY_REFRESH_NOT_SUPPORTED_ERROR`) for deploy-key / generic `git` rows — there is no provider to ask. `RepositoryRecord.metadata` is typed by `RepositoryMetadata` (also `lastInspectedAt` / `lastInspectedCommitSha`, written by a successful inspect)
- `deleteRepository(id)` → `DELETE /api/client/v1/repositories/:id` — **409** `source_referenced_by_compose` (`REPOSITORY_REFERENCED_BY_COMPOSE_ERROR`) while a stored compose still names the repository in `x-turbopanel.source.sourceId`; the UI renders that as "disconnect it from the service first", never as a retryable error. The error **literal** is unchanged.
- `fetchGitConnections()` → `GET /api/client/v1/repositories/connections`; `fetchConnectionRepositories(connectionId)` → `GET …/connections/:id/repositories` — every repository read mints a short-lived provider credential on the instance, so the picker only fetches once a connection is chosen
- `createGitlabDeployKey({ name })` → `POST /api/client/v1/repositories/gitlab/deploy-keys` — returns `{ ok, secretId, publicKey, fingerprint }`; the public half is returned **once** and never retrievable again; generate it before creating the repository
- `githubAppInstallUrl()` / `gitlabOauthConnectUrl()` — browser-navigate targets (`GET …/repositories/github/install` / `…/repositories/gitlab/oauth`, query `forgeId=`), **not** fetchable: both answer **302** to the provider's consent page and the operator has to land there to approve the grant. `fetch` would consume the redirect and show nothing
- `fetchTags(scope?)` → `GET /api/client/v1/tags` with **exactly one** optional parent query (`serverId` / `workspaceId` / `projectId` / `environmentId` / `serviceId` / `datacenterId` / `storageId`); `setEntityTags` is `PUT /markers` replace-all. `fetchTasks({ serviceId } | { environmentId })` → `GET /api/client/v1/tasks` (the two filters are mutually exclusive). A scheduled **task** is configuration only — nothing runs yet — and is unrelated to the compose-level `x-turbopanel.cron` block already handled by `src/lib/compose/cron.ts` and `src/components/org/compose-cron-fields.tsx`
- **Draft project surface** (create wizard, compose type): `ProjectProvider` accepts an optional `draft: ProjectDraft`, so the wizard renders `ProjectShell` + `ProjectOverviewTab` against a synthetic `ProjectRecord` (id `draft`) that has no row yet. Everything below the provider is unchanged — same shell, breadcrumb, `layout.contentMaxWidth`, Overview · Compose · Services tabs, editor, linter, graph. Hosting / Servers / Storage / Settings are omitted (`DRAFT_COMPOSE_PROJECT_TAB_IDS`) because a draft has no environments and no row to configure. The draft branch only changes what cannot exist yet: **queries are parked** (`useProject`/`useEnvironments`/services/containers/storage/bindings all disabled) so the synthetic id never reaches the API; scope is forced to Project (`baseSelected`, no environments); the shell shows `DraftLensTabs` (Overview · Compose · Services) driven by `draft.setSection` instead of the project tab bar, because there is no route to navigate; the header rename calls `draft.onProjectNameChange` instead of `PATCH /projects/:id`; the tabs and the environment header do not render (no environments, and the shell skips drafts); and **Save is suppressed entirely** (`hideSave`, and no Overview toolbar trailing) because there is no row to patch. The wizard commits from its own **bottom-right Create project** button below the shell, which calls `POST /projects` once with the type, the workspace, and `options.compose`. `draft.onDraftChange` mirrors debounced edits back into wizard state so Back → Type → Compose does not lose the YAML, and `null` from it (unparseable YAML) disables Create rather than shipping stale text. The surface opens on the tab the chosen card names — **Compose** or **Services**, never Overview. `/[projectId]/setup` lands the same way after `configure`, via `projectComposeSectionHref(…, option.section)`. Do not add a second compose editor for the create flow.
- Compose UI: Overview edits **base or this environment's settings** depending on the path (`/overview` → `project.options.compose` via `persistProjectCompose`; `/environments/:id` → `environment.options.compose` via `persistEnvironmentCompose`), both through the shared `compose-persistence.ts` helpers, and the environment editor still collapses to service status dots once containers exist. `ComposeEditorSection` accepts optional `onDraftChange` (debounced, `null` while YAML is unparseable). **Preview Deployment** (`PreviewDeploymentModal`) shows Merged / Prepared compose via the environment header **⋯** menu (inspect; Merged keeps service `x-turbopanel`) or deploy confirm — see **Overview Compose panel** above. Docker Compose project name is the TurboPanel project UUID; container names are service UUIDs (`containerNaming: uuid`). Deploy enqueues compiled runtime **`compose.yaml`** (`role: 'runtime'`). Preview **Prepared** shows compiled `compose.yaml` and per-server blocks when scheduled. `compose-editor-section.tsx` (Compose | Services) on project and environment detail. Placement is **not** stored in compose (instance validation rejects `x-turbopanel.placement`; UI strips it before save). The active tab is persisted in `presentation.editorView` (`editor` \| `visual`) on that compose document when saved — project base and each environment overlay keep their own preference (`readComposeEditorView` / `setComposeEditorView`); the YAML textarea and every read-only compose view show **native Docker Compose only** — all `x-turbopanel` metadata (top-level and per-service) is hidden via `hideComposeTurbopanelExtensions` / `stripComposeManagedExtension`, preserved through a name-keyed shadow, and re-attached on parse/save; edit those fields on the **Services** tab. Below the YAML editor (not in its text) the Compose tab lists the hostnames the file sets, read-only and in plain words (`compose-hosting-readonly.tsx`; the Hosting screen links to it with `?hosting=<service>`). **Services** form tab (`compose-visual-service.tsx`, view id `visual`) binds a Git repository via `SourceSection` (`git-sources/repository-picker.tsx` — application → account → repository, attaching on pick); it shows labeled **Name** (service key rename), optional **Description** (`x-turbopanel.description` — TurboPanel-only metadata), a single **How is this served?** picker (`Container image` / `Caddy` / `nginx` / `Apache` / `OpenLiteSpeed` / `Node app` — one control for what used to be three: Service kind, Deployment mode chips, and Web engine; selecting an engine writes `serviceKind: site` + `engine`, so no schema change was needed) with a read-only request-path line under it (`Docker → Traefik → Caddy → :443`, `Caddy → Caddy → :443`, …) so containers and sites are described in one vocabulary, and for containers **Image** + **Tag** when there is no Dockerfile/`build` (joined into Compose `image:` via `parseComposeImageRef` / `formatComposeImageRef` in `src/lib/compose/image-ref.ts`); when a Dockerfile is present, Image/Tag/Registry are hidden (image is built on deploy — adding Dockerfile clears `image`; removing Dockerfile restores `nginx:alpine` if none remains); a site shows relative **document root** instead of an image, plus a **PHP** block (`x-turbopanel.php`) with the version picker, the common settings, and an Advanced disclosure for opt-in extensions and worker tuning. PHP moved off the hosting row: a pool is keyed by (environment, compose service), so several hostings on one service silently last-wins merged. Extensions offer only the _optional_ list — the baseline is always installed — and the hint says an extension loads for every site on that PHP version on the server, because `extension=` is `PHP_INI_SYSTEM` and PHP has no per-pool loading. A `node` service instead shows **Framework** chips and **Node version**. **Registry** is an Add chip for alternate registries (`ghcr.io`, `quay.io`, `localhost:5000`, … — Docker Hub when omitted; only offered when Image/Tag are shown); digests round-trip when already present. Optional **Dockerfile** section (Add chip `Dockerfile` → Compose `build.context: .` + `build.dockerfile_inline` via `build-ref.ts`; platform-split `dockerfile-editor.*` — CodeMirror on web, monospace `TextInput` on native) is removable; external path-based builds render read-only with convert-to-inline. Inline edits are picked up on **Cacheless redeploy** or when `service.options.build.disableCache` is set. Optional Compose fields come from `VISUAL_SERVICE_FIELDS` in `src/lib/compose/visual-fields.ts` — flip `offerAdd` to expose an "Add …" button (currently **Restart** + **Dockerfile** — not Container name (`uuid` naming owns Docker names unless **Keep original container names**; the field still renders when YAML already has `container_name`); Compose Spec restart policies `no` / `always` / `on-failure[:max-retries]` / `unless-stopped`, default `always`). Ports stay editable when already present in YAML but are not offered as an Add button yet. **Compose** edits YAML with managed fields hidden and preserves `#` comments on save; a **Compose linter** (`lintComposeYaml` in `src/lib/compose/lint.ts`) runs live on both tabs (`ComposeLintPanel`) and flags invalid YAML, unknown top-level/service keys (with edit-distance "did you mean" hints — e.g. `imaage` → `image`), services missing `image`/`build` (site via hidden extension list), and author-typed `x-turbopanel` when managed extension is hidden, with 1-based line numbers sorted ascending (errors before warnings on the same line); badges/messages are red for errors and yellow for warnings. It gates save — client disables save when blocking issues exist, and the instance rejects `options.compose` with **400** `compose_invalid` + `issues` (same linter; empty-draft “no services” warnings are allowed). **Enter** auto-indents (2 spaces, deeper after `key:`), right-trims trailing spaces/tabs on every line, and re-indents a just-finished service-only key (`restart`, `image`, …) when it was left too shallow under `services:` (e.g. `restart: always` at column 0 → nested under the current service); top-level keys that are also service keys (`networks`, `volumes`, …) are left alone. **Tab** / **Shift+Tab** indent/outdent by two spaces via `src/lib/compose/yaml-indent.ts` (client-side; save still re-stringifies with the `yaml` package). The field itself is platform-split behind `compose-yaml-editor.tsx` (shared `ComposeYamlEditorProps`/`ComposeYamlEditorHandle` types in `compose-yaml-editor-types.ts`): **web** (`compose-yaml-editor.web.tsx`) is a real **CodeMirror 6** editor (`@uiw/react-codemirror`) with line numbers, indentation-guide lines (`@replit/codemirror-indentation-markers`), YAML syntax highlighting, and lint diagnostics in the gutter (`src/lib/compose/lint-diagnostics.ts` adapts `ComposeLintIssue[]` to CM `Diagnostic[]`; the `ComposeLintPanel` list stays below as the detailed view) — CM owns Tab/selection/smart-indent on web, with a custom Enter keymap reusing `indentAfterNewline` for parity; **native** (`compose-yaml-editor.native.tsx`) keeps the original transparent-`TextInput`-over-highlight-overlay approach (`src/lib/compose/yaml-highlight.ts` for muted comments + red/yellow lint-line tinting and the fixed-width `●`/`▲` gutter marker).
- `EnvironmentRecord.serverId` / `updateEnvironment(id, { serverId })` — placement pin SoT; compose never carries placement. `stripComposePlacement` is an input-sanitization path only (strips any `x-turbopanel.placement` a client might still submit); there are no read/write placement helpers — UI placement UX uses `serverId` only
- `fetchVisibleProjects(workspaceId?)` → `GET /api/client/v1/projects` (optional `?workspaceId=` filter)
- `fetchProjectCatalog()` → `GET /api/client/v1/project-catalog` — returns `{ catalog: CatalogSummary[] }`
- `fetchProject(id)` → `GET /api/client/v1/projects/:id`
- `createProject(body: CreateProjectBody)` → `POST /api/client/v1/projects`

- `fetchEnvironmentShares` / `addEnvironmentShare` / `removeEnvironmentShare` → `GET`/`POST /environments/:id/shares`, `DELETE .../shares/:shareId` (send exactly one of `serviceId`, `storageId`). `EnvironmentSharesPanel` lists what an environment uses from the shared folder and offers shared services and volumes of the project's other environments; **409** `asset_not_common`, `asset_in_this_environment`, `asset_has_no_owner`.
- `fetchOrgPrincipals(orgId)` → `GET /api/client/v1/organizations/:id/principals` (owner/manager). `deleteOrgPrincipal(orgId, principalId)` → `DELETE .../organizations/:id/principals/:principalId` (a system user whose project is gone; **409** while anything uses it).
- `fetchServerPrincipals(serverId, orgId?)` → `GET /api/client/v1/servers/:id/principals` (owner/manager); `fetchServerPrincipalRemovalPlan(serverId, orgId?)` → `GET .../servers/:id/principal-removal-plan`. `deleteServer` takes `principals` (only the ones to delete outright; the rest are kept) and maps `principal_delete_refused` / `principal_not_on_server` to `ServerPrincipalChoiceRefusedError`.

- `createEnvironment` takes `start: 'copy' | 'empty'`; `updateEnvironment` takes `pinned`; `makeEnvironmentPrimary(id)` → `POST /api/client/v1/environments/:id/primary`. `EnvironmentRecord` carries `isPrimary` and `pinned`.
