# Admin area (`/admin/*`) — AGENTS.md

Repo-wide rules (design system, tokens, platform copy, testing): `../../../AGENTS.md`.

Instance-wide administration for users with the `admin` or `superadmin` role.

## Layout

- `src/app/admin/_layout.tsx` — role guard (`superadmin` or `admin` via `isAdminSession`); non-admins redirect to their dashboard
- `src/lib/admin-navigation.ts` — area registry (`ADMIN_AREAS`); add entries + routes together
- `src/components/admin/admin-shell.tsx`, `admin-sidebar.tsx`, `admin-header.tsx` — responsive shell (mirrors org console); header has **Return to instance** (org-switcher slot) via `ReturnToInstanceSegment` → preferred org dashboard; sidebar nav uses `AdminAreaIcon` per area

## Areas (routes)

| Route | Component | Purpose |
|-------|-----------|---------|
| `/admin/access` | `access/hostnames-section.tsx` | **Hostnames** — every address this control plane answers on. `PUT /api/admin/v1/instance/hostnames` is **replace-all**: the body is the full `{ hostnames: [{ host, source, uploadedCertId }] }` set, and a 422 carries `{ error, invalid }`. Entries are still **composed** (`src/lib/public-url-entry.ts`): scheme, host, optional port. A pasted address is absorbed and anything past the port is dropped. **Scheme-less** stored entries (`panel.lan`, `panel.lan:8443`) display as https and are left byte-for-byte alone because they expand to port **8443** in an install command. Each row keeps its own certificate source (`platform-ca`, `uploaded`, `lets-encrypt`). `/admin` redirects here. `/admin/networking` stays as a bookmark redirect to `/admin/access` and is not an admin area |
| `/admin/access/certificates` | `access/certificates-section.tsx` | Uploaded pairs (label, PEM upload, wildcard coverage, attach/detach) and instance-only Let's Encrypt settings (contact, terms, directory, staging) plus per-hostname reachability and last error. Independent of any organization's ACME opt-in |
| `/admin/access/trusted-proxies` | `access/trusted-proxies-section.tsx` | Read-only effective `TURBOPANEL_TRUSTED_PROXY_CIDRS`. The variable **replaces** the loopback default (`127.0.0.0/8`, `::1/128`); it does not append. Include loopback when Caddy is still co-located |
| `/admin/access/tunnel` | `access/tunnel-section.tsx` | Write-only co-located tunnel token. The API never returns the stored value. An empty token tears the tunnel down |
| `/admin/access/platform-ca` | `access/platform-ca-section.tsx` | Platform CA fingerprint, subject, validity, PEM download, and `server.tls.trust.reconcile` fan-out. Deno only — Workers answers 422. This is the **Platform CA**, never an Organization CA |
| `/admin/updates` | `updates-section.tsx` | Control plane and co-located daemon. Each row shows the installed version and the channel target, including the manifest commit when one is present. The control-plane row also names the UI package target installed by that upgrade. Control-plane Upgrade dispatches then waits through the restart (`waitForUnitUpdate` polls `GET /instance/updates` until the installed commit matches the target, or the version when the manifest has no commit). Daemon Upgrade is a normal dispatch. Trunk has no control-plane package, so that Upgrade stays disabled |
| `/admin/email` | `email-settings-section.tsx` | System email provider (SMTP / Mailgun) |
| `/admin/auth-providers` | `auth-provider-settings-section.tsx` | GitHub and Google OAuth client credentials |
| `/admin/git` | `git-sources/git-sources-section.tsx` | **Instance-wide** Git provider applications — a *collection*, not a pair of singletons: several GitHub Apps and GitLab OAuth applications may coexist (a github.com App and a GitHub Enterprise one, separate Apps per customer account, gitlab.com beside a self-managed GitLab). Each row shows its own webhook URL, which carries that app's routing ref so a delivery names its app before any secret is checked. Secrets are write-only: the API reports presence only, so an untouched field is omitted from the PATCH and the stored secret survives. **Create a GitHub App** expands in place (never a modal) and asks whether the App should live on the operator's **personal GitHub account** or a **GitHub organization** (the `github.com/<login>` slug — not a TurboPanel organization id) before POSTing the manifest. GitHub creates the App with the scoped webhook URL already set and hands back every credential in one hop; the instance then **302s** the browser to this page (`?created=` or `?error=`), never leaving the operator on the API JSON. The same component serves `/<orgId>/projects/git-sources` with `scope="org"`, where an organization manages its own apps and sees instance-wide ones as `readOnly`. **Open** goes to `/admin/git/[appId]` here and to `/<orgId>/projects/git-sources/[appId]` there; the admin detail screen hides **Repository access**, because an installation belongs to an organization and an instance-wide view has no account list of its own to show |
| `/admin/signup` | `signup-settings-section.tsx` | Public sign-up enable/disable (`IS_SIGNUP_ENABLED` DB setting) |
| `/admin/secrets` | `secrets-reencrypt-section.tsx` | Superadmin **Re-encrypt secrets** sweep — re-seals at-rest `tpsecret` blobs (variables, TLS keys, principal passwords) onto the current data-encryption key version |

## Instance API

Admin helpers in `src/lib/instance-api.ts` (`ADMIN_API = '/api/admin/v1'`):

- `fetchInstanceHostnames()` → `GET /api/admin/v1/instance/hostnames` — `{ ok, hostnames }` (`host`, `source`, `uploadedCertId`, `status`, `notAfter`, `acmeLastAttemptAt`, `acmeLastError`)
- `saveInstanceHostnames(hostnames)` → `PUT /api/admin/v1/instance/hostnames` — **replace-all**. The body is the complete set. A 422 throws `InstanceHostnameValidationError` with `invalid: string[]`
- `applyPublicUrls(urls?, signal?)` → `POST /api/admin/v1/instance/public-urls/apply` (Deno self-hosted only). **The Access screen calls this with no body.** Hostnames are already persisted by the replace-all PUT; `useApplyPublicUrls` → `requestPublicUrlsApply` posts `applyPublicUrls(undefined, signal)`, so the JSON body is omitted. Passing `urls` is only the older flat-list caller. **This request routinely dies in flight, and that is not a failure.** Applying regenerates the Platform CA leaf and reloads Caddy — the hop the browser is talking through — so the caller usually sees `HTTP 502` from Caddy or from a Cloudflare tunnel in front of it while the apply in fact succeeded. `useApplyPublicUrls` absorbs that: `isControlPlaneRestartError` in `src/lib/control-plane-recovery.ts` classifies the failure, and `waitForControlPlaneRecovery` polls **`fetchInstanceHostnames`** (the hostname recovery probe) until the control plane answers again. That probe is both the liveness check and the proof of what landed: the saved hostname set is compared with the set the probe returns. Outcomes are `applied` / `reconnected` / `not-saved` / `unreachable`, rendered by `publicUrlsApplyFeedback` in `src/lib/public-urls-apply.ts`. Do not probe `fetchPublicUrls` for this recovery — the hostname rows are the source of truth the apply just wrote. The classifier leans on an `apiFetch` detail: it appends `: <message>` only when the control plane itself answered with a JSON body, so a **status-only** `HTTP 502` is by construction something in the middle talking — which is what keeps a real `503 no co-located daemon connected` from being swallowed as a restart. Keep that formatting (`formatFetchFailureDetail`) intact. The `signal` bounds a socket the reload left hanging (120 s, under the control plane's own 180 s apply timeout)
- `fetchPublicUrls()` → `GET /api/admin/v1/instance/public-urls` — flat projection kept in sync with `origin` for cert SANs and webhook reachability. The Access editor reads hostnames, not this list
- `savePublicUrls(urls)` → `PUT /api/admin/v1/instance/public-urls` — writes that flat projection as `platform-ca` origins. The Access screen uses `saveInstanceHostnames` instead
- `fetchInstanceCertificates()` / `uploadInstanceCertificate({ label, certPem, keyPem })` / `attachInstanceCertificate(id, hosts)` → `GET`/`POST /api/admin/v1/instance/certificates` and `PATCH /api/admin/v1/instance/certificates/:id/hostnames`. The private key is never returned. `hosts` is the **full** attachment set; names dropped from it stay published as `platform-ca`
- `fetchInstanceAcmeSettings()` / `saveInstanceAcmeSettings(updates)` → `GET`/`PUT /api/admin/v1/instance/acme` — contact email, terms, directory URL, staging. Instance-only; not an organization's ACME opt-in. Env-sourced keys are read-only
- `fetchInstanceDaemon()` → `GET /api/admin/v1/instance/daemon` — `{ applicable, connected, serverId, version, capabilities }`. Workers returns `{ applicable: false }` and must not be polled (`useInstanceDaemon` sets `staleTime`, no interval)
- `fetchInstanceUpdates()` → `GET /api/admin/v1/instance/updates` — `{ channel, units: { instance, daemon } }`. The instance unit includes `uiTarget`, the UI package on the same channel. Installed control-plane version is `INSTANCE_VERSION`. `requestInstanceUpdate()` → `POST /api/admin/v1/instance/updates/instance` and `requestColocatedDaemonUpdate()` → `POST /api/admin/v1/instance/updates/daemon` return `{ ok, dispatched }` (202). The control-plane post is not awaited through the install: `useUpgradeInstance` treats a status-only 502/503 as a restart and polls this GET until the installed commit matches the target commit (or the version, when the manifest has no commit) (`applied` / `reconnected` / `unreachable`)
- `fetchTrustedProxies()` → `GET /api/admin/v1/instance/trusted-proxies` — **read-only** `{ cidrs, isDefault }` from `TURBOPANEL_TRUSTED_PROXY_CIDRS`. The variable replaces the loopback default
- `setInstanceTunnelToken(token)` → `POST /api/admin/v1/instance/tunnel-token` — **write-only** `{ token }`. An empty token tears the tunnel down. The response is `{ ok: true }` and never includes the stored token
- `fetchPlatformCa()` → `GET /api/admin/v1/instance/platform-ca` — `{ ok, fingerprintSha256, subject, notBefore, notAfter, pem }` or `{ ok: false }`. Workers answers 422
- `reconcilePlatformCaTrust()` → `POST /api/admin/v1/instance/platform-ca/trust-reconcile` — enqueues `server.tls.trust.reconcile`; `{ ok, enqueued }`
- `fetchSignupSettings()` / `saveSignupSettings(enabled)` → `GET/PUT /api/admin/v1/settings/signup` — panel toggle for public sign-up (`IS_SIGNUP_ENABLED`); **409** when env force override is set
- `fetchAuthProviderSettings()` / `saveAuthProviderSettings(settings)` → `GET/PUT /api/admin/v1/settings/auth-providers` — GitHub/Google OAuth client id/secret; env-overridden keys are read-only; secrets are write-only (`***`)
- `fetchGithubAppSettings()` / `saveGithubAppSettings(patch)` → `GET/PUT /api/admin/v1/instance/github-app` — GET returns presence only (`hasPrivateKey` / `hasWebhookSecret`, never the value); PUT takes a partial patch, so omitted keys keep their stored value and an explicit `null` clears a nullable one (`appSlug`, `clientId`, `webhookSecret`). `appId` and `privateKeyPem` reject empty strings — never send `''`
- `fetchGitlabOauthSettings()` / `saveGitlabOauthSettings(patch)` → `GET/PUT /api/admin/v1/instance/gitlab-oauth` — same presence-only / partial-patch contract; `baseUrl` is always resolved on read (defaults to `https://gitlab.com`)
- `GITHUB_WEBHOOK_PATH` / `GITLAB_WEBHOOK_PATH` (`/webhook/github`, `/webhook/gitlab`) mirror `turbopanel/src/app/surfaces.ts` by hand (different repo and runtime). Webhooks are a top-level traffic class, not an API surface — every layer fronting the instance forwards `/webhook/*` explicitly. `gitWebhookHint(origins, provider)` in `src/lib/git-webhook-url.ts` reproduces the instance's `webhookReachability()` rule: first publicly routable https origin wins, otherwise the first origin plus the LAN note. The unreachable notes point at a **manual deploy** (each service's declared branch), not at the `ref` field on `POST /environments/:id/deploy` — the control plane still answers `501 source_ref_unsupported` to any request that sets it. `gitWebhookHint` takes an optional `webhookRef` **and** the app's `baseUrl`: hosted providers get the clean `/webhook/github`, self-hosted ones get `/webhook/github/<ref>` because GitHub Enterprise and self-managed GitLab ship on their own cadence and the App-id header is not a safe single point of failure there. Mirrors `webhookPathFor` on the control plane. `forge-detail-section.tsx` renders the `webhookUrl` the API already resolved and calls the helper only for the reachability note, **only on resolved data**: `usePublicUrlsOptional()` returning `undefined` renders a loading row and a real fetch failure renders an error notice, because feeding `[]` from an unresolved query would tell a configured operator they have no public URL (a 403 is different — the hook folds that into an empty list on purpose)
- `applyReencryptSecrets(body?)` → `POST /api/admin/v1/secrets/reencrypt` (superadmin only; bounded batches — pass prior `cursor` until `completed`; returns `{ ok, scanned, reencrypted, skipped, failed, completed, cursor }`; **409** `reencrypt_in_progress` when another sweep is running)

When apply returns 422 with `"cert apply is not applicable on this runtime"` (Workers), hide the Apply button and show an informational note instead.

`useCan` is display-only; rely on server 403s and `handleUnauthorized()`.
