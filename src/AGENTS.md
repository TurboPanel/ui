# Source Tree Rules — AGENTS.md

### TypeScript style (SonarQube)

- Prefer **`String#replaceAll()`** over **`String#replace()` with a global regex** when replacing every occurrence of a substring (`typescript:S7781`).
- Use **`String.raw`** for string literals that contain backslashes so escapes stay readable and correct (`typescript:S7780`).
- Prefer **optional chaining** (`obj?.prop`) over `!obj || obj.prop` (`typescript:S6582`).
- Avoid **nested ternaries** — use `if`/`switch` or helpers (`typescript:S3358`).
- Extract helpers when **cognitive complexity** exceeds 15 (`typescript:S3776`). Closures inside a component (async handlers, JSX callback props, `.map` bodies) are charged to the component at +1 nesting, so move logic into a custom hook, a module-level helper, or a child component rather than another inline arrow.
- Sort strings with **`.sort((a, b) => a.localeCompare(b))`** (`typescript:S2871`).
- Mark React component props **`Readonly<{…}>`** (`typescript:S6759`).
- Do not leave **`TODO`** in code — use `Future:` in a normal comment (`typescript:S1135`).
- Avoid widening unions with bare **`string`** when a literal union exists (`typescript:S6571`).
- Web-only CSS (`position: 'sticky'`, `overflowX`, `backdropFilter`, …) is not in RN `ViewStyle` — cast via `as unknown as ViewStyle` (same pattern as `src/lib/glass.ts`). Do **not** use `as const` on those objects inside `StyleSheet.create` or `tsc` fails.


The class theme lives in `global.css` (its `@theme` block is generated from `src/lib/theme-palettes.ts` by `uniwindThemeCss()`; a test keeps them equal), the Metro wrapper in `metro.config.js`, and the colour and layout tokens in `src/lib/theme.ts`. `src/uniwind-types.d.ts` is generated by Metro, committed so `tsc` and CI see class names, and never edited by hand.

## Stack

- **Expo SDK 58** (React Native 0.88, React 19.3) — keep Expo module versions aligned with `pnpm expo install --fix`. Native `ios/` / `android/` are not checked in (CNG).
- **Styling** — new and rebuilt UI uses Uniwind classes (`className="..."`, Tailwind 4 syntax) with the token theme from `global.css`: `bg-surface-2`, `text-text-3`, `border-sep`, one class colour per palette token, each pointing at the same `--tp-*` variable that drives Light / Dark / Match Computer on the web and falling back to the Navy value on a phone. Existing `StyleSheet` code moves over gradually as screens are rebuilt; do not convert a screen as a side effect of another change. Never hard-code a colour in a class (`bg-[#123456]`) or add one to `global.css`; change the palette. Do not use the `dark:` variant for colours: the `--tp-*` variables already follow the theme, and a second switch would disagree with the saved choice. Write whole class names (a lookup table, never `bg-${tone}`): the class scanner reads source text. Arbitrary values (`text-[11px]`, `tracking-[0.4px]`) keep sizes exact; the stock text sizes also set a line height. No base reset is imported on purpose, so a screen that is not converted looks the same as before. `src/components/ui/badge.tsx` is the reference conversion.
- **React Query** `^5.90.14` — see [Server state (React Query)](./lib/queries/AGENTS.md).
- **Fonts** — `RootLayout` registers everything through `useFonts` and returns `null` until the fonts are ready. v4 type is Plus Jakarta Sans (700; 800 italic for page titles), Geist (400 / 500 / 600) and Geist Mono (400 / 500 / 600), packaged from `@expo-google-fonts/*` and bundled as same-origin assets: on the web `font-src 'self' data:` already covers them (`scripts/hosted-security-headers.test.ts` keeps it that way), and no font host is linked. Each weight is its own family name (`Geist_500Medium`); `src/lib/v4/typography.ts` maps roles to those names and never sets `fontWeight` beside them, because a phone applies it unreliably to a custom font. A test keeps the `useFonts` map and the role table equal. A new font weight needs the same three steps: `pnpm add`, a `useFonts` entry, a role in `typography.ts`; then `pnpm notices:generate`.
